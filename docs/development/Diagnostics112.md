## Capture correction

Before attempting a severe/unhandled dump, the capture-only debugger now saves an independent numeric exception/context report, bounded instruction/stack/register-address fragments and cached module ranges. Each read reports its actual byte count/error; missing context is explicit. Module sizes/names come from debug load/unload events and backing-file PE headers, avoiding dependence on fault-time Toolhelp enumeration. Snapshot creation never overwrites an existing report.

For partial/read failures, the writer makes at most three attempts under distinct names: the original request; a readable-memory variant; then a minimal dump. Failed files remain preserved. Successful reduced coverage is explicitly labeled. Permanent output failures stop retrying. [Microsoft MINIDUMP_TYPE documentation](https://learn.microsoft.com/en-us/windows/win32/api/minidumpapiset/ne-minidumpapiset-minidump_type) describes MiniDumpIgnoreInaccessibleMemory and its omission of unreadable regions. This fallback cannot promise a complete dump of a corrupted process; the independent report is separate evidence.

The default binary still excludes hardware tracing and passes the Diagnostics111 PE capability/import policy. No game code/data writes, injected modules, new hooks, game settings or gameplay changes are introduced. Only the recorder executable is replaced while the game is closed; exact rollback is preserved. The original watcher, autorun, baseline, input/lifecycle helpers and D: destination remain unchanged. Fresh user launch/READY and loaded/capture verification remain required before formal play.

## Verification

Eight native writer/cache/snapshot cases cover normal writing, injected partial-read fallback, minimal fallback, exhausted retries, permanent-error stop, cached resolution and no-overwrite behavior. Three resulting dumps are decoded and checked for their actual full/minimal streams. Four full-session cases retain normal exit, handled fault, native crash and safe detach. Three real debug-event snapshots verify registers, readable stacks/code and cached module names.

A separate toy deliberately corrupts only its own loader pointer while raising a handled access violation, then restores it in native SEH. All three real dump attempts fail, but the independent context/stack/module report survives and the toy exits normally. This reproduces the class of evidence loss; it does not prove the real game had that specific loader-pointer corruption. The initial x86 SIZE_T compile failure is retained alongside final passes. Test source and receipts are separate from real private crash evidence.

Source is in tools/diagnostics/source/native/crash_capture112.h and the existing crash_recorder.cpp. Build tools/diagnostics/build111.py without the experimental flag, then run source/verify_capture112.py against a new evidence directory and the configured private support root. Building/testing does not install or launch the game. The installed recorder and future real acceptance are recorded independently; this is a capture repair, not a native battle-crash fix.
