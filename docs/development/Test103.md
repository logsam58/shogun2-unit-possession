# Test103 / v0.16: contextual targeting, input ownership and knockdown recovery

Test102 user play reported that following and gait mostly worked, but Q attacks did not and possession dropped repeatedly. A further report described manual movement while knocked down by cannon fire. Test103 is a local correction candidate; offline checks and live acceptance are separate.

Q retains stock RMB single/double click and formation drag. Before a tap commits, it runs the original cursor refresh and hover-provider update at the crosshair. During an authorized Q gesture, the original native ray-hit filter runs first, then same-unit soldier/mount hits are excluded so the player's own formation cannot take the target before an enemy behind it. Native target metadata, attack eligibility, terrain/building obstruction, preview, order choice, formation geometry and packet submission remain in the engine. This is an own-unit occlusion filter, not a custom enemy search or attack packet. Other units and terrain/building hits remain intact. The filter requires current full camera/actor/unit/lease identity and the native window thread.

Owned WASD is now also masked in the game's polled keyboard stream, with held-key draining on exit. Physical input used by the mod is unchanged; native Shift/Ctrl modifiers remain available for Q. The existing camera-input dispatcher is suppressed only with current full possession proof. A new guarded native soldier-cycle hook prevents switching the camera actor while that proof holds; release, stale identity and native control forward normally. These changes prevent established native mutation paths without repairing pointers after an ownership failure or loosening a guard.

The Test102 recording establishes three living identity releases: two stage11 followed-actor mismatches and one stage21 selected-group failure, without an exit key in the recorded input. It does not identify the actual writer or prove that all three share one cause. Native cycling is reproduced offline, but its involvement in those live events is an inference. Test103 adds a bounded private release snapshot containing current camera/manager actor pointers, selected-group data and actor identity/state to distinguish any remaining failures. No pointer/time grace is added.

Manual translation and manual weapon handling are blocked in native prone postures12/13 and during the current knockdown/fall/get-up clips. The original posture transition table34f7e0 maps12/13 to0 using FACE_DOWN_GET_UP455 / FACE_UP_GET_UP456, so posture0 alone is not recovery completion. The gate follows the actual active474 animation until the native clock clears it; a stale planned clip does not keep the lock. Native collision, impulse, vertical physics, root animation and get-up progression still run. No arbitrary timeout, actor pinning, velocity wipe or extra movement speed is introduced.

Two native hooks are added: camera cycle2f79a0 (RET8) and cursor result filter10ee5b0 (RET8). Existing shared numeric protocols, including Command10080 bytes, remain unchanged. Test102 follow catch-up, Q single/double and Z captured-anchor semantics are retained. HUD and QTE source/binaries are unchanged, with earlier validation retained rather than claimed as freshly rerun.

The new fixture executes production ownership/input/motion guards and bounded original native camera cycling, hit construction, hover update and animation clock/cleanup. Scene hits, per-target metadata/eligibility, window host, view count and motion integrator are explicit substitutions. It reproduces own-formation occlusion and camera actor replacement; it cannot certify real attack execution, destructible eligibility, native AI/path completion, every recovery asset or the cause of every live release. Recorded user play remains required. No fix for the known extended-play effects crash is claimed.
