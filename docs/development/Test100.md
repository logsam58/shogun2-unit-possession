# Test100: unit controls and self visibility

Unpublished development candidate based on v0.15. Live acceptance is pending. The published release and historical accepted/installed snapshots are preserved.

Q routes the existing game window procedure's WM_RBUTTONDOWN, WM_MOUSEMOVE with MK_RBUTTON, and WM_RBUTTONUP. Native decoder RVA BD4A10 maps these to ordinary events 5, 12 and 4; stock battle dispatcher 10FB980, cursor 2F7350, placement provider and renderer handle the rest. No independent frontage calculation, custom gold line/dots/width label or Q movement-packet builder is used. Q freezes personal mouse-look and releases the pointer during the gesture, then resumes normal look. Physical weapon clicks are isolated while Q is held. Focus/ownership/exit cancellation runs original cursor cleanup on the window thread without the order-commit layer; delayed cleanup carries a generation tag and current root/environment/vtable proof.

E uses native halt. Z snapshots numeric player position/yaw at keypress, resolves current native ground and atomically queues facing-move plus guard. C updates the native formation goal at the player rather than six metres behind. Native paths/formations/width remain the game's. R cycles native hold/at-will policy; command mode uses existing task hooks, full current owner/peer proof and fixed bounded per-actor/shot permissions. A native shot can finish all its release markers; a new draw cannot inherit the old permission. Other units and ordinary modes retain original forwarding. No extra native hook, global OS input injection or growing command history is added.

Self visibility is separate from ranged-pose eligibility. It hides validated head/neck branches without swallowing arms or weapon sockets. Original skin-ready caches the raw native head position before the render palette is hidden. Reused palettes first retire only the exact matching prior presentation; actor serial, lease, holder, model binding, asset and byte equality guard restoration. Death rig behavior remains native. Body/shoulder clipping in every possible animation is not certified.

The optional Command100 numeric status is 80 bytes. Existing status, equipment, ammunition, accuracy, climb, QTE snapshot/publication and commitment layouts are unchanged. Root adapter logs record native Q press/move/release/cancel counts, fire permissions and self-visibility counts; the existing automatic recorder already preserves those logs.

Offline validation uses original native constructor/serializer, mouse decoder, cursor lifecycle, scene-query glue and skin-ready/cache methods in a private relocated image. Game/window hosting, vector/context allocation, world/nav/height providers, cursor refresh/snapshot primitives and peer release events are fixture substitutions. No game DllMain or live battle runs in these fixtures. Actual native game-window dispatch, native frontage display, full unit AI volleys, collision/animation lifecycles and roster/map coverage require a fresh recorded live session. Effects-crash and mounted-bow limitations remain unresolved.
