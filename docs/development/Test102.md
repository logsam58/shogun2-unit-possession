# Test102 / v0.16: contextual orders and native formation pace

This local development build retains Test101's native Q placement, stationary-follow correction and first-person presentation. Test101 received user feedback of "BIG improvement" after exact loaded/capture verification; that is not a complete live certification.

Q uses the stock RMB context at the crosshair: ground movement, enemy attack or a supported destructible-target action. A tap maps to native single click; a completed quick second tap maps to native double click (mouse decoder events7/6), letting the game choose run/charge and contextual action. Hold/drag remains native. There is no custom attack target search, packet, frontage or formation overlay. Native target eligibility and weapon/unit restrictions apply. A drag or long hold cannot arm a later accidental double tap; focus loss, ownership reset and other commands clear it. Windows double-click time defines the interval; autorepeat is ignored.

Z immediately walks to the position/facing captured at the first press and enables native guard. A second tap within the Windows double-click interval upgrades that same numeric anchor to native run plus guard. It does not move the anchor when the player moves/looks between taps. Current lease/actor/unit and native camera ownership still authorize each command; stored target coordinates do not grant ownership.

Follow Me requests native run while its current same-unit peer formation center is over4m away. It keeps catch-up until within2m, then matches the player's current walk/run selection. The band avoids repeated gait changes. Native run permission, terrain, fatigue, formation/path completion and individual stragglers remain controlled by the game. Shift does not create a separate third sprint speed. Crouch lock, opposing movement keys and mounted steering without translation do not request matching run. A pace-only update retains the last formation goal/facing; mouse/body yaw alone cannot issue an order. Samples and changes are bounded to250ms; there is no growing history or per-frame command flood.

The stock consumer checks15cb80 before running. This is decoded analysis, not original source. Existing signature/engine checks and strict ownership remain. Regression coverage executes production input/follow service and original constructors/serializers, with synthetic current actor/peer records, fixture scene/window providers and substituted native run predicate. Full native target classification, attack execution, casualty/morale/path completion and run animation require recorded user play. HUD/QTE code and binaries are retained without claiming fresh render or timing runs. Known effects crash and mounted-bow limitations remain unresolved.
