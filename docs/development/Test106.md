## Rendering and ownership

Four graphics API entry points are discovered through private dummy device vtables: DXGI Present/ResizeBuffers and D3D9 device Present/Reset. No additional Empire.Retail.dll hook or gameplay layout changes. Hooks forward original arguments/results exactly; TEST presents, foreign windows and shutdown skip composition. Each successful pair is installed together; partial pair creation is removed. Only the current process's native SHOGUN 2 window is handled. Resize/reset release resources only for the retained matching chain/device. Hook/trampoline storage remains resident until process exit, consistent with the adapter's existing lifecycle. Explicit stop clears GPU resources; process termination relies on OS reclamation rather than calling driver COM cleanup from CRT destructors under loader lock.

DirectX11 uses a separate ID3D11DeviceContextState, restoring the game's previous context after each layer. DirectX9 uses an all-state block plus explicit render-target, depth and viewport restoration. Premultiplied BGRA pixels blend with ONE/INV_SRC_ALPHA. Textures are reused until dimensions/device or image identity changes. The compositor does not read/write native actor objects, simulate weapons, change camera matrices, change graphics preferences, or alter unit tasks.

An optional bounded numeric/pixel channel106 carries current lease/actor/unit, image number, dimensions/rectangles and submission acknowledgement. Existing numeric gameplay/QTE protocols remain byte-compatible. HUD/QTE active images require the currently published owned lease, actor/unit, mode, ready, heartbeat and stop/release state. Death lids use the same retained death-view lease. Immutable QTE result/interruption pixels may finish their existing bounded feedback window with the exact matching numeric publication; this grants no gameplay permission and never repairs a native pointer. Invalid, torn, inactive or stale publications are rejected. If the publisher is busy writing its next DIB, the compositor may reuse only its completed, still-fresh pixel snapshot and must reprove the current numeric lease on that draw. Copying uses a separate pending buffer so a failed sequence check cannot corrupt the retained image. This avoids publication-phase flicker without native identity grace.

Acknowledgement is written only after native Present succeeds, with the QPC time of that call. Failure/occlusion cannot hide fallback. This is submission evidence, not proof of physical scanout or measured input latency. QTE retains32 image snapshots and binds input Frame93 to the acknowledged snapshot, rejecting reused slots or a different lease/actor/unit/QTE serial. A newer CPU render cannot silently supply geometry for an older native image. Existing authoritative deadlines, freeze/feedback, pause, minimum three seconds plus one cycle, and native-tick drift correction remain.
