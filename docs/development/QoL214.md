# Revision40 candidate: Deck controls and possession HUD

This candidate is based on accepted revision39. Offline checks passed and the
owner approved installation on PC and Deck; both installed packs and exact39
rollback backups were independently verified. It is not uploaded or accepted in
a live game. The current accepted release identity remains39.

## Controls

- Deck possession: R4 toggles slow/normal speed; R5 pauses/resumes. Hold B to crouch.
- Hold R1, tilt the right stick toward a command, then release R1 to order. The
  four sectors are Follow Me (up), Stop (down), Hold Here (left), and Fire Orders
  (right). B cancels. The D-pad does not select a wheel sector. Outside the wheel,
  the D-pad keeps abilities/ammunition and camera-distance actions.
- PC possession: ALT toggles slow/normal speed on release. F remains climb and
  E remains Stop. Alt chords/focus loss do not activate slow motion.
- Deck Menu requests the native game menu without ending possession, and sends
  native Escape during an active battle-intro movie. Native menus/results take
  keyboard/mouse priority while possession stays alive.
- Campaign RT double-taps use the native double-click message. Selection-type
  cycling is allowed while native city details are open; other modal panels keep
  map controls blocked. Double-click focus explicitly releases its mouse press,
  preventing later pad movement from turning that press into box selection.

Battle RTS right-pad click holds Space to show formations/ranges; A is unbound.
Left-pad directional clicks send native relative formation-movement orders,
including both components of diagonal input. Click-and-drag sends the native
rotation order; touching/swiping without clicking has no action. Shoulder zoom
and the accepted thumbstick camera are preserved.

## HUD and resources

The unit card keeps the native portrait aspect ratio and shows formation activity
beside unit weapon mode. Activity is a read-only observation of current living
formation peers, excluding the player: paired melee first, a live native ranged
cycle next, then a moving-peer quorum; otherwise Holding. This is an observed
summary, not a new unit AI order or a claim to expose an engine aggregate getter.

The identity card remains bottom-left, the ability panel is upper-right, and
Unit Orders sits separately midway down the right. The raised/LMB Fire panel is
omitted. Ammo is labelled in full above its meter.
A native yellow/red framed strength bar shows ammunition remaining divided by
native starting ammunition. No numerical ammo count is displayed. Unit melee-mode
status remains the formation's state even while the player's personal weapon is
readied for a ranged shot. Fire/reload/traversal and combat-commitment guards remain.

Textures, unit cards, clan mons, native icons, fonts and audio are still prepared
locally from each user's owned game. No reference-image pixels or extracted game
assets are added to the package. Steam supplies controller glyphs locally.

The portrait reader uses the live unit definition's native info_pic/icon_name
aliases, plus faction-specific uniforms entries in the player's local packs.
It reads enabled PFH2/PFH3 mod packs, base/patch packs and automatic movie packs;
there is no stock-unit allowlist. Optional TGA, PNG and DDS (BC1/2/3/7 or RGB/A)
images are decoded in bounded memory, fit without stretching, and never copied
to a persistent card cache. The 16-entry/32MiB pixel cache owns its memory;
missing, malformed or unsupported cards fall back without hiding the HUD.
No universal promise is made about ambiguous movie-pack collisions or pack
formats the original game itself does not use. New mod cards and replacement
stock paths are covered by isolated fixtures, not every installed Workshop mod.

On Deck, the campaign end-turn corner is enlarged15%. Supported native hover
widgets are enlarged up to50%, including their existing native fonts and children,
then constrained to the current logical viewport. This does not re-enlarge the
previously fitted campaign modal panels or change PC UI sizing.

## Native evidence and boundaries

The original Shogun2 stock and reviewed Bugfix engine images were decoded privately.
Additional native spans in native214_generated.h contain ranges and hashes only.
They guard the original PanelManager.OpenPanels predicate, speed getter/order
producer, and native font layout methods. UI geometry uses the existing guarded
Resize/MoveTo/Position routes on the current owning UI thread, with ancestry,
identity, dimensions, roster and lifetime checks. No engine code bytes are shipped.
Modal, speed and font admission are scoped independently so an optional Deck
font/speed conflict does not disable unrelated PC possession.

Battle speed uses the original native order producer and its own commander checks;
multiplayer, replay and movies are refused. This is not a direct simulation write.
Screensaver recovery reasserts existing action handles/sets on focus return or a
bounded inactive-input interval. It does not reinitialize Steam Input, rewrite the
player layout on focus changes, or establish the exact cause of the reported loss.

Offline regression fixtures exercise actual original-image UI methods and guarded
native predicates, plus explicit speed/font providers; they are not a running game.
Hardware checks are still required for screensaver recovery, intro skipping,
city-details cycling, tooltip appearance, menu/results visibility and the personal
ranged override. Preserve accepted cameras, charge/climb, infantry/cavalry movement,
and revision39 melee cleanup. Separated-player enemy acquisition is unresolved.

No recorder, debugger, routine input logging or new storage collector is included.
Staging requires separate approval, closed receiving game/launcher and exact rollback.

## Revision41 native corrections

Formation fine tuning now begins one native manoeuvre preview and commits on
release. Holding does not repeat orders. Press toward a direction to nudge;
left/right strafe. Click-drag turns instead. Diagonals produce a single combined
destination for each selected unit, with its heading preserved. The native
point builder, movement constructor and serializer are reused. Existing camera
behavior is unchanged.

R4/R5 use the original BattleTimerControl selector and pause/resume methods when
that controller is present. LB/RB inside city details use its original regional
callbacks, rather than map selection. START queues a short native Escape pulse
through the existing input owner, including the transition into battle intros.

These corrections have isolated original-code coverage; real Deck behavior is
still a separate test. Fresh Ghidra assembly is required for unknown native
calls. One recovered cancel pseudocode signature omitted a stack argument; the
original-code fixture caught it and the RET4 signature was corrected.
