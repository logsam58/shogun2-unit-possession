# Test130 / v0.22: separate player control from native squad coordination

Test128 and Test129 were rejected in live play. This candidate changes the control boundary instead of adding another firing-readiness exception.

The retail engine has two distinct links: actor+0x214 supplies unit ownership and shared properties; actor+0x3b4 links the soldier to a native SQUAD controller. Test130 retains the first and removes the second using native removal routine 0x1a80a0. The unit's master entity roster, physical actor identity, camera holder, secondary groups and mount/passenger links remain intact.

A native unit-control callback at 0x1b7ed0 synchronizes detachment before and after the unit's work. Only the freshly proved controlled actor and reciprocal mount qualify. Native squad insertion 0x14bc50 and transfer 0x1b33f0 are guarded for those actors, and an exact candidate-loop boundary at 0x1afed6 prevents automatic regrouping from collecting them again. Every other soldier and non-SQUAD group follows the original code. No private native objects or replacement unit rosters are allocated.

Only an exact native formation-movement task is retired on detachment, using native cancellation, while paired combat and wall-climbing tasks are protected. On leaving possession or switching soldiers, native insertion rejoins a surviving actor at the next live unit callback. Current unit serial, environment, original roster membership, actor identity and current registered squad lists must prove restoration is safe. Death, serial reuse and a new battle discard stale records without writing to former objects. If an explicit stop happens while the game is paused, restore-only unit and personal combat compatibility hooks remain resident until a native update can rejoin the actor. Reassignment guards stop immediately. If a preferred squad is no longer registered, rejoin uses the unit's current registered main squad. Restoration records are fixed-size; there are no growing event queues or diagnostic logs.

The original-native integration fixture covers ordered and unordered squad compaction, up to 1,000 members, ordinary peer transfers, unchanged unit ownership/master rosters, real regroup candidate collection, formation arrival and firing movement aggregates without enabling the Test128/129 predicate exceptions. AI peers must still satisfy their own checks. Lifecycle coverage includes 13 invalid-control/exit cases, switching soldiers, reciprocal mounted control, current-squad replacement, task cancellation, shared native walk/run modifiers, 100,000 cheap peer rejections and 1,000 detach/rejoin cycles.

Native personal idle/movement combat tasks continue to run. Two tasks assume squad position/facing and squad contact bookkeeping exist. Their scoped compatibility uses the detached actor's current absolute position and facing instead of a missing squad, and skips only that actor's missing-squad bookkeeping. It never invents or assigns a replacement SQUAD pointer. Current native physical identity authorizes these read-only adaptations until actual rejoin, including the short interval after control stops. A fixed numeric negative filter rejects unrelated actors before locks or native identity scans; a positive filter hit grants no authority. The fixture checks 100,000 unrelated rejections. Other actors and real squad contexts retain original behavior. Native position and heading blocks, all eight SIMD registers and arithmetic flags, ordinary peers, pending rejoin, exceptions and serial reuse have direct fixture coverage.

These are isolated native fixtures. The unit callback and personal combat task bodies, formation policy and task resource providers are substituted; complete live scheduling, autonomous targeting and projectile dispatch still need the user's battle test. The initial fixture had an invalid synthetic active task with a null vtable; its failure is preserved under artifacts/Test130/initial-fixture-failures. Correcting that fixture did not change production behavior for the failure. A later new fixture had compile-only main-macro/assembly separator errors, also preserved. The first full passing suite is preserved under before-combat-compatibility and superseded by the final suite with these additional compatibility checks. A later expanded adapter run was intentionally stopped for the deferred-stop correction; before-deferred-stop-correction marks it incomplete rather than passing evidence.

Accepted Test127 Follow Me audio and Test126 camera/entry behavior remain unchanged, as do the exact HUD and QTE binaries. Earlier scoped firing waits remain installed, but the new native aggregate fixture proves squad detachment independently of them. Product remains v0.22; this is an unpublished candidate, not a GitHub release. Recorder and debugger stay off. Existing Ultra/crowd performance and crash limitations remain unresolved.
