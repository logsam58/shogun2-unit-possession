These notes cover implementation and validation. The [player guide](../../README.md) and [release description](v0.20.md) cover playing and installing the mod.

## Input and crowd work

QTE input reads the latest native acknowledgement directly instead of waiting for the renderer to poll it again. A fixed 32-entry synchronized numeric history checks current battle, actor, unit, lease and prompt serial. The 50 ms freshness limit, simulation deadline, pause behavior and native outcome authority remain. The old path reproduced 36 misjudgements of an already-presented successful image; the corrected fixtures match all 36. This is software geometry/input evidence, not physical scanout or end-to-end hardware latency proof.

Unrelated readable infantry encounter groups use one 80-byte stack snapshot. Failed or short snapshots fall back to the original individual-field reads. Possible matches still use the original current owns/member/release proofs; no cross-callback positive cache or grace period is added. The focused Test114 path used 23 reads / 86 bytes; the Test115 readable foreign path uses 1 read / 80 bytes. Differential/current-identity/fallback coverage includes 5,152 cases and 100,000 encounters. These prove the bounded read reduction, not a universal FPS fix.

The adapter's global exclusive pose lock remains unchanged. Sampled lock-return frames occurred in both earlier traces and the later no-significant-lag reference. They establish contention in a crowd-sensitive callback, not total off-CPU waiting or the cause of every slowdown. A correction still requires production concurrency, ownership, restoration and death fixtures plus the full adapter checks.

## Gameplay implementation

Movement, fatigue, ammunition, reload, projectile creation, unit orders and formation/pathfinding stay connected to the game's own systems. The circular first-person spread cone converts effective unit accuracy with fixed calibration; it is not identical to stock rectangular scatter or a certified stock hit-probability match. Descending reticle dashes are not calibrated range marks.

Presentation applies a closer near plane only to the owned living first-person camera, rotates infantry weapon-look around the current eye and preserves raw head/shoulder cache data and restoration checks. Committed combat supports horizontal look up to 100 degrees either side of the animated head, plus vertical look, while retaining native translation/roll and animation/root-motion timing. Death and stale ownership have separate cleanup paths.

The friendly-fire observer accepts a tracked personal projectile's direct hit on a living ally. AI, enemy and stale-projectile events are rejected. Cropped local-game PCM plays asynchronously in the HUD process, with overlap dropped rather than queued. Area-only explosions, secondary effects and every weapon/device combination are not certified.

The [source map](../../SOURCE_MAP.md) identifies the active files. The [architecture](../ARCHITECTURE.md) covers forwarding, ownership and shared numeric layouts.

## Validation

Fresh release checks were loader (2 executables) and the full final installer suite: exact Test115, local-v0.19 and historical predecessor upgrades; seven interruption stages per predecessor; repeat-install backup retention. A stale Windows 0.19 version resource was rejected before packaging, corrected to 0.20, and the complete final installer suite rerun. Retained gameplay evidence is adapter (61) and HUD (5) from Test109 and QTE (39) from Test115. These gameplay suites were not rerun for release metadata alone. Seven Python dump-format tests also passed.

Packaging verified the five embedded payloads, PE 0.20, source closure, package CRC/content and a read-only installer target check. The source archive contains 442 exact Git blobs from the tagged commit. All six uploaded assets were downloaded and SHA256 verified before publication. No game installation or launch was part of publication.

A five-minute Test115 reference retained 305.07 seconds of target CPU samples, 299.07 seconds of frames, 19,021 frames and 44 sampled visible QTE serials. The player reported no significant lag. Recorded event-loss and property-error counters were zero, but 12 focus-filtered frame intervals exceeded 100 ms. This is a smooth-play reference, not reproduction of the earlier severe slowdown or a controlled same-scene baseline. Software Presents are not physical display timing. Raw traces and recordings remain outside Git.

## Crash evidence

Captured immediate failures include:

- `Empire.Retail.dll+14A4011`: effects-table read with a null table.
- `mss32.dll+16EB9`: Miles sample-loop read with an invalid negative remaining count.
- `DirectSound+5DEFA`: invalid virtual-method call. The relevant capture had blood disabled. Caller bytes matched the relocated system backing file in first-chance and unhandled dumps.
- `Empire.Retail.dll+32B474`: a later engine access violation, followed 15 ms later by an `AUDIOSES+4A912` exception on another thread. All four dump attempts were empty after partial-read failures, so the runtime object/stack and original corruption are not established.

These are distinct immediate faults, not a proved common cause. Native module attribution does not exclude indirect mod involvement. Recorded resource headroom does not rule out every allocation or hardware fault. Turning blood off did not prevent every captured crash. No crash patch is included in v0.20.

Diagnostic startup hardware-tracing failures were a separate regression and were withdrawn. Real-game recording uses the capture-only debugger; experimental hardware tracing remains prohibited. See [Diagnostics110 recovery](../development/Diagnostics110-startup-recovery.md), [Diagnostics111](../development/Diagnostics111.md), [Diagnostics112](../development/Diagnostics112.md) and the [recorder guide](../../tools/diagnostics/README.md).
