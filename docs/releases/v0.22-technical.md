# v0.22 technical notes

## Shipped checkpoint

v0.22 preserves the exact Test124 adapter, HUD and QTE binaries. The maintained native source is byte-for-byte aligned with that gameplay source. Only release metadata, packaging and predecessor recognition change during promotion; the release loader and installer are built separately. Publishing does not replace the installed candidate.

This retains the v0.21 crowd improvements, HUD, unit controls, acknowledged-image QTE input and friendly-fire voice. The Test116 clock and Test117 render-copy experiments remain excluded from active gameplay.

## Initial encounter filtering

Test124 rejects clearly unrelated, unprepared melee encounters before calculating their complete native context and participant positions. The predicate reads a bounded current prefix. Possible player matches repeat full validation and participant reads; an unavailable prefix falls back to the original path. There is no cross-callback cache, changed native call count, tick-rate change or change to QTE timing.

Five alternating fixture runs of 20,000 foreign preparation dispatches reduced callback reads from 47–67 to 26–28 and median path CPU time by 37.71–55.92%, depending on infantry/mounted and participant count. The production dispatch and real memory reads were exercised with substituted native prepare/selector actions. These are offline path measurements, not game FPS.

## Audio guard

Test123 reproduced a zero-sample overrun in the supported Miles audio library. The adapter guards that specific entry only after verifying the complete library hash and instruction prefix. Zero-count calls return the corresponding empty-work result; nonzero calls use the original trampoline. The library and trampoline remain resident to avoid teardown races. Unsupported libraries or failed hook setup leave the guard inactive. The stock audio DLL on disk is unchanged.

The native fixture covers 64 zero-count states, 512 bit-exact positive-count cases, the stock fault before hooking and after disabling, wrong-hash rejection, trampoline forwarding and restoration. This addresses the reproduced zero-count defect; it does not establish the cause of every historical effects/audio crash or prove general crash safety.

## Performance acceptance

The player selected this checkpoint for v0.22 after reporting smooth play throughout with Large unit size, one massive army per side and maximum graphics in DX11. This is subjective configuration-specific acceptance. No new FPS trace or loaded-build gate was taken for that report; Test124 was the last verified installed build. Earlier Test124 reports included severe slowdowns, and Ultra units with substantial army presence remain problematic.

Both earlier observations remain relevant: some close RTS views stayed smooth while possession slowed down, and the six-army Ultra stress case was slow in RTS too. Hardware/engine scaling is plausible, but an unavoidable limit or absence of mod overhead has not been established. The CPU 0–3 comparison gave no noticeable benefit and was restored. No CPU, graphics or recorder changes are bundled in this release.

## Validation

Retained gameplay evidence comprises 62 adapter fixtures from Test123, 46 QTE fixtures from Test124 and five HUD fixtures from the retained Test122 HUD. The preparation fixture covers 16,000 frozen membership comparisons, 1,000 repeated membership transitions, mutation after filtering, failed-read fallback, inaccessible boundaries and native forwarding/output. Promotion retains these results and exact gameplay binaries rather than reporting new gameplay runs.

Release loader and final installer checks cover embedded payloads, exact published-v0.21 and Test124 upgrades, seven interruption stages for each and repeated-install backup retention, alongside historical fixtures. The [validation receipt](v0.22-validation.json) separates fresh release checks from retained gameplay evidence. Package versions, source closure and uploaded download checksums are verified independently.
