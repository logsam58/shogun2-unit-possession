# v0.24 technical notes

## Accepted gameplay and release scope

v0.24 retains the exact accepted Test138 adapter, HUD and QTE binaries and all356 files in the preserved native output source. Promotion changes the release metadata, build defaults, predecessor recognition and packaging. Gameplay is not recompiled. The installed Test138 development wrapper remains in place; the new release wrapper is not installed or live-tested during publication.

The user reported "Worked phenomenal." after a fresh Test138 battle gate verified exact loaded components, native hooks, Steam context and actual automatic capture. Acceptance covers the tested gameplay with first-person weapon/arm presentation explicitly deferred. It does not establish all-roster coverage, measured FPS or universal crash safety.

## Changes since v0.23

Rapid Advance uses exact active native-effect identity. During that effect, Shift's final speed is capped by a bounded sample of eligible same-unit AI horizontal velocities, with identity keys, cache expiry and a native boosted-walk fallback. Walking remains available. Ordinary Shift and other abilities are unchanged; native AI stats/orders are not modified.

Q target filtering gives proven enemy hits priority over friendly foreground actors while retaining normal native hit metadata. The actual native UI action is rebound to1 for unit melee mode. Native unit state remains the authority for personal synchronization and the original-art HUD indicator. Melee-only units ignore the action;2 has no weapon binding.

Personal melee readiness retains native state/animation dispatch for supported projectile families, including empty ammo and mounted riders. Ordinary native locomotion states0/4 pass unchanged through both the animation hook and equipment synchronization boundary. Paired combat, traversal and recovery keep their established authority. This deliberately removes the rejected expanded combat gait rather than declaring the first-person model presentation finished.

One captured crash showed an owned detached actor's advance task3eba00 calling the original17bee0 reader without its primary squad. Existing idle/move context did not cover that task. The advance callback now scopes the same strictly validated actor context and restores TLS on return or exception. Deferred shutdown retains compatibility until rejoin. There is no fake squad or general null-query bypass. This addresses a concrete mod compatibility gap, not every historical crash.

## Validation

Retained Test138 evidence includes79 adapter fixtures. The presentation fixture compares ordinary hooked calls against the original native result from identical actor bytes, including native refusal. Native state/pose/turn coverage spans the supported projectile catalog; the crash fixture executes both original failing read blocks and verifies scoped forwarding, identity, exceptions and rejoin. Native task/resource providers are stated in the development notes; final renderer/blend/mesh appearance is not certified offline.

HUD6 and QTE46 evidence is retained for exact binaries/source. Release promotion runs fresh loader2, complete final-payload installer and Python7 checks. The installer includes the exact accepted Test138 predecessor and earlier development/published predecessors, all seven interrupted stages and repeated-backup retention. The [release receipt](v0.24-validation.json) pins the complete native/tool source closure, binary hashes, actual checks and retained evidence.

## Remaining limits

First-person weapon/arm quality, mounted-bow presentation, Ultra crowd slowdown, other crash paths and incomplete roster/map/display coverage remain unresolved. Native infantry/cavalry charging is the next checkpoint; T/G original-icon abilities and variable bow draw are not implemented here. Publication does not launch/install the game, start extra tracing or change recorder, CPU/affinity or graphics settings.
